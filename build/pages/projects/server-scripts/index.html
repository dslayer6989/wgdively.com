Server scripts.

Four small Bash scripts for an Ubuntu home server. They're short enough to read in a minute, and you should read them before you run them. Each one was checked with ShellCheck and tested on Ubuntu.

Getting a script onto your server: copy the download link, then on the server run curl -fsSLO followed by the link. Open it with less to read it, then run it with bash. Nothing here pipes straight from the internet into your shell.

Read-onlyNo sudo needed

health-report.sh

One screen telling you how the server is doing: uptime, memory, disk space (warns at 90%), temperature, waiting updates, failed services, Docker containers that are unhealthy or stopped, and whether the internet and DNS work.

curl -fsSLO https://wgdively.com/scripts/health-report.sh
bash health-report.sh

safe-update.sh

Installs all Ubuntu updates without asking questions, keeps your existing config files if a package wants to replace one, tidies up old packages, and logs everything to /var/log/safe-update.log. Give it your compose folder and it updates those containers too. It tells you if a restart is needed, but never restarts by itself.

curl -fsSLO https://wgdively.com/scripts/safe-update.sh
sudo bash safe-update.sh              # packages only
sudo bash safe-update.sh ~/homelab    # packages + containers

docker-cleanup.sh

Docker quietly fills disks with old images and build cache. This shows what it would remove and asks first. It removes stopped containers, unused networks, untagged images and build cache, and leaves your volumes (your data) and any image a container is using alone.

curl -fsSLO https://wgdively.com/scripts/docker-cleanup.sh
bash docker-cleanup.sh          # asks before deleting
bash docker-cleanup.sh --yes    # no question (for a schedule)

backup-folder.sh

Makes a dated .tar.gz of a folder (your homelab folder, say), checks the archive opens, and deletes the oldest backups so only the newest few remain. Point it at a USB drive or a second disk. A backup on the same disk won't save you if that disk dies.

curl -fsSLO https://wgdively.com/scripts/backup-folder.sh
bash backup-folder.sh ~/homelab /mnt/usb/backups 7

Databases (like Uptime Kuma's) are safest to back up while their container is stopped: docker compose stop, back up, then docker compose start.

Run them on a schedule

Run sudo crontab -e, add lines like these, and save. The cron explainer turns the times into plain English. Move the scripts somewhere permanent first, for example sudo install -m 755 *.sh /usr/local/bin/.

# Every Sunday at 4:00 — updates (packages + containers)
0 4 * * 0  /usr/local/bin/safe-update.sh /home/YOU/homelab
# Every day at 3:30 — back up the homelab folder, keep a week
30 3 * * *  /usr/local/bin/backup-folder.sh /home/YOU/homelab /mnt/usb/backups 7 >> /var/log/backup.log 2>&1
# First of the month at 5:00 — Docker clean-up
0 5 1 * *  /usr/local/bin/docker-cleanup.sh --yes >> /var/log/docker-cleanup.log 2>&1
